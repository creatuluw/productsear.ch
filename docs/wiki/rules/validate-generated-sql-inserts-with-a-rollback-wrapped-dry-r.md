# Validate generated SQL inserts with a rollback-wrapped dry run against the live DB

**Guideline:** Before declaring a generated/hand-written INSERT or migration SQL file ready to run, execute it against the real database inside a single `BEGIN;` … `ROLLBACK;` transaction — never commit the validation pass.

What the dry run proves with zero side effects:

- **Syntax and escaping** — real Postgres parses the actual file (apostrophes, emoji, long descriptions in repo titles), not an approximation.
- **Constraints and shape** — row counts, distinct-URL counts, id ranges can be SELECTed and asserted inside the same transaction.
- **Idempotency** — run the file **twice** inside the one transaction and re-count; a missing `ON CONFLICT DO NOTHING` clause surfaces immediately (this caught a real bug on 2026-11-06 in `scripts/insert-missing-repos-active-30d.sql`, which initially claimed idempotency in its header but omitted the clause).
- **No collateral damage** — ROLLBACK leaves positive-id rows (the external-sync mirror) exactly as before, which matters because `te9_dev.bookmarks` is a production-fed mirror you don't want exploratory writes in.

When it applies: any time SQL is generated by a script or written by hand for the Railway `te9_dev` database — ingest files, migrations, backfills. Cheap, fast, and the only failure mode is forgetting the ROLLBACK. See [[insert-missing-repos-active-30d-sql]] for the applied example.
