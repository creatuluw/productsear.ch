# insert-missing-repos-active-30d.sql

## What is it?

`scripts/insert-missing-repos-active-30d.sql` — idempotent SQL that inserts the **522 still-active missing GitHub repos** (see [digital-products-repos-activity-split-csvs](./digital-products-repos-activity-split-csvs.md)) into `te9_dev.bookmarks`, shaped to match existing github.com bookmark rows: `type='link'`, `domain='github.com'`, `tags`/`note` NULL, title `owner/repo: description`, `raindrop_created_at` = the source bookmark creation date from the digital-products export.

## What it documents

- [repo-scan-pipeline](../entities/repo-scan-pipeline.md) terminal stage — the ingestion handoff: scan → missing-repos → activity check → this file
- Generated by `.archive/repo-scan/gen-insert-sql.js` (re-run to regenerate from the CSV); 9 INSERT statements × 60 rows, `ON CONFLICT (id) DO NOTHING`
- **Negative synthetic id convention**: `id = raindrop_id = -1 … -522` (stars-desc file order, -1 = highest stars). Both real sequences are strictly positive (internal id ≤ 2.4M; raindrop_id 363M–1.9B), so negative values can never collide with rows written by the external Raindrop→DB sync. Fixed ids + ON CONFLICT make re-runs no-ops.

## Details

- **Location**: `scripts/insert-missing-repos-active-30d.sql`
- **Format**: plain SQL, schema-qualified `te9_dev.bookmarks`, follows repo migration-file conventions (no explicit transaction wrapping)
- **Validated** 2026-11-06 inside a BEGIN…ROLLBACK dry run: 522 rows in, 522 distinct urls, double-run still 522, zero effect on positive-id rows
- **Executed** 2026-11-06: 3,838 → 4,360 bookmarks; 522/522 embeddings (voyage-4-large, search_tsv present) + 522/522 archetypes backfilled; confirmed searchable on prod
- **Rollback**: `scripts/rollback-insert-missing-repos-active-30d.sql` — deletes children-first (`bookmark_archetypes`, `bookmark_embeddings`, `bookmark_content`, `bookmark_analysis` where `bookmark_id < 0`) then `bookmarks` where `id < 0`, in one transaction. Dry-run verified: removes exactly the 522, never the positive-id rows
- **Caveat** (in file header): `bookmarks` is an external-sync mirror; if the sync ever switches to full DELETE+reload these rows are wiped — re-run the file to restore
- **After running**: nightly embed-new-bookmarks workflow picks the rows up automatically (`embed-bookmarks.ts` embeds any bookmark lacking a `bookmark_embeddings` row)
